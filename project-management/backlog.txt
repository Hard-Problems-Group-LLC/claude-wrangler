`install.sh` aborts on stock macOS bash 3.2 (review POSIX-2, added
2026-10-12T05:40:00-07:00). With no arguments, `local
stage_2_args=("$@")` and the later `"${stage_2_args[@]}"` expansion
fail under `set -u` in bash before 4.4 ("unbound variable"), so the
documented `./install.sh` Quick Start stops before stage 2 on a default
Mac; passing any argument, or a newer bash first on `PATH`, works
around it. `install.sh` is TheKnowledge-managed and must not be edited
or refreshed from this Windows checkout, so carry the fix upstream with
the FieldManual items above: exec with `"$@"` directly (main never
shifts) or use `${stage_2_args[@]+"${stage_2_args[@]}"}`, apply
`CDPATH= cd --` to the managed root scripts' `cd "$(dirname ...)"`
lines, and add a macOS CI step that runs `/bin/bash install.sh` with no
arguments against a stub stage 2. Blockers: FieldManual availability.

Strengthen the Windows verification stamp (review SEC-1 follow-up,
added 2026-10-12T05:40:00-07:00). On Windows the stamp records size and
modification time only, because `st_ino` differs between Python
versions on ReFS (Dev Drive). An archive that preserves modification
times could therefore satisfy it; a git clone or pull cannot. Evaluate
a version-independent file identity (for example the 128-bit
`FILE_ID_INFO` read through `ctypes` on both sides) and whether the
stamp should move outside any path a repository can supply. Also
evaluate whether the WSL side should stamp a Windows-carried Linux
binary automatically instead of needing one plain install there.
Blockers: none.
